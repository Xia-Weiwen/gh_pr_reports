# AI Analysis of Pull Requests for sgl-project/sglang during 20260614-20260621

1. **Key Takeaways**: This week's development is characterized by a major architectural shift toward a unified, polymorphic `BaseRunner` system that converges eager and CUDA-graph execution paths, alongside aggressive performance tuning for DeepSeek-V4/Qwen3.5 on AMD ROCm and Blackwell. Total PRs: 572. Top active areas: (1) Polymorphic Runner refactoring, (2) AMD `aiter` and `DeepEP` kernel fusions, (3) PD Disaggregation transfer optimizations, and (4) Speculative Decoding v2 feature parity.

2. **Core Architecture & Runner Refactoring**
    *   Introduced `EagerRunner` to handle non-graph execution via fixed-size static input buffers, moving away from grow-on-demand registries [PR#28386](https://github.com/sgl-project/sglang/pull/28386), [PR#28379](https://github.com/sgl-project/sglang/pull/28379).
    *   Refactored `AttentionBackend` to unify metadata storage. Renamed `init_cuda_graph_state` to `init_static_metadata_buffers` to reflect its role in both eager and graph paths [PR#28763](https://github.com/sgl-project/sglang/pull/28763), [PR#28768](https://github.com/sgl-project/sglang/pull/28768).
    *   Converged metadata building bodies (eager, capture, and replay) into a single `_compute_forward_metadata` helper per backend to eliminate code duplication [PR#28765](https://github.com/sgl-project/sglang/pull/28765), [PR#28767](https://github.com/sgl-project/sglang/pull/28767).
    *   Centralized speculative weight-update logic in the scheduler via `get_model_runners` to handle target and draft workers consistently [PR#28548](https://github.com/sgl-project/sglang/pull/28548), [PR#28710](https://github.com/sgl-project/sglang/pull/28710).
