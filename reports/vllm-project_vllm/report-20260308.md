# AI Analysis of Pull Requests for vllm-project/vllm during 20260301-20260308

**Key Takeaways:** This week’s 585 PRs signify an aggressive push toward production-readiness for Blackwell (SM120) and ROCm architectures, alongside the structural decoupling of the V1 engine for advanced scheduling, with primary activity in (1) Blackwell/Hopper kernel fusions for FP8/NVFP4, (2) Qwen3.5/DeepSeek-V3 architecture stabilization, (3) V1 ModelRunner and Async scheduling migration, and (4) comprehensive tool-calling/reasoning parser refinements.

### 1. Core Architecture & V1 Engine
* **V1 Engine & ModelRunnerV2:** Massive migration efforts continue with `ModelRunnerV2` now supporting XPU [PR#36078](https://github.com/vllm-project/vllm/pull/36078), pipeline parallel warmups [PR#36280](https://github.com/vllm-project/vllm/pull/36280), and extensible `CUDAGraph` dispatch [PR#35959](https://github.com/vllm-project/vllm/pull/35959).
* **Scheduling Optimizations:** Introduced `--tensor-parallel-size-attention` to decouple attention parallelism from FFN TP, enabling higher DCP ratios for GQA models [PR#36287](https://github.com/vllm-project/vllm/pull/36287). Fixed a critical KV-cache head-of-line blocking issue where a single heavy request stalled the scheduler [PR#36390](https://github.com/vllm-project/vllm/pull/36390).
* **Speculative Decoding Decoupling:** Draft-token hooks are being decoupled from the speculative decoding gate, allowing plugins (like dLLM schedulers) to reuse the data path [PR#36391](https://github.com/vllm-project/vllm/pull/36391).
* **Distributed Services:** Added Expert Parallel Load Balancing (EPLB) support for MiniMax M2 [PR#36134](https://github.com/vllm-project/vllm/pull/36134) and optimized DeepEP communication with double-buffered chunking [PR#35958](https://github.com/vllm-project/vllm/pull/35958).

### 2. Hardware Backends & Kernel Optimizations
* **NVIDIA Blackwell (SM120/121):** Enabled FlashInfer FA2 MLA backends for consumer Blackwell [PR#36322](https://github.com/vllm-project/vllm/pull/36322) and implemented software E2M1 conversion shims for NVFP4 activation quantization where hardware instructions are missing [PR#35947](https://github.com/vllm-project/vllm/pull/35947).
* **ROCm Expansion:** Enabled Cascade Attention for AITER FlashAttention to improve prefix caching performance on MI300/355 [PR#36227](https://github.com/vllm-project/vllm/pull/36227). Optimized `fused_topk_bias` by leveraging AITER kernels over slow PyTorch fallbacks [PR#36252](https://github.com/vllm-project/vllm/pull/36252).
* **Quantization Fusions:** New Triton kernels for fusing `GemmaRMSNorm` + FP8 quantization [PR#36016](https://github.com/vllm-project/vllm/pull/36016) and `BF16` BMM + FP8 static quantization for MLA `_v_up_proj` [PR#36297](https://github.com/vllm-project/vllm/pull/36297).
* **Intel XPU & CPU:** Added support for int8 compute mode in CPU AWQ/GPTQ via OneDNN [PR#35697](https://github.com/vllm-project/vllm/pull/35696) and upgraded OneDNN for AArch64 int8 matmul support [PR#36147](https://github.com/vllm-project/vllm/pull/36147).

### 3. Model Support & Multi-Modality
* **Qwen 3/3.5 Ecosystem:** Extensive fixes for `GatedDeltaNet` (GDN) sharding [PR#36242](https://github.com/vllm-project/vllm/pull/36242), Marlin TP failures [PR#36329](https://github.com/vllm-project/vllm/pull/36329), and video embedding path crashes [PR#36332](https://github.com/vllm-project/vllm/pull/36332).
* **DeepSeek V3.2 & MLA:** Support for fused FP8/NVFP4 output quantization in MLA attention [PR#36205](https://github.com/vllm-project/vllm/pull/36205) and KV transfer support for sparse attention indexers [PR#35965](https://github.com/vllm-project/vllm/pull/35965).
* **New Architectures:** Added native support for BERT-like Chinese ERNIE pooling models [PR#36385](https://github.com/vllm-project/vllm/pull/36385), FireRedASR2 [PR#35727](https://github.com/vllm-project/vllm/pull/35727), and Kimi-Audio-7B [PR#36127](https://github.com/vllm-project/vllm/pull/36127).

### 4. Speculative Decoding & Structured Outputs
* **EAGLE & MTP:** Accelerated MTP (Multi-Token Prediction) for DeepSeek V3.2 and Qwen3 [PR#35882](https://github.com/vllm-project/vllm/pull/35882) and added `Jump Decoding Guidance` [PR#36142](https://github.com/vllm-project/vllm/pull/36142).
