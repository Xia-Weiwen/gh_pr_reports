# AI Analysis of Pull Requests for vllm-project/vllm during 20260322-20260329

1. **Key Takeaways:** This week's development is centered on the stabilization of the V1/Model Runner V2 architecture and the aggressive optimization of DeepSeek-R1 and Qwen3.5 model families across NVIDIA Blackwell and AMD ROCm 7.2.1 platforms, with 502 PRs prioritizing (1) hardware-specific kernel fusions for latent attention (MLA), (2) advanced quantization formats like NVFP4/MXFP4, and (3) resilient disaggregated prefill/decode orchestration.

2. **Core Architecture & Model Runner V2**
    * Refined the V1 engine's visibility by exposing `num_skipped_waiting_reqs` to distinguish between fresh arrivals and requests blocked by transient constraints like LoRA budget [PR#38435](https://github.com/vllm-project/vllm/pull/38435).
    * Implemented a custom lightweight graph splitter `_vllm_split_module` to replace `torch.fx.passes.split_module`, reducing cold-start compilation overhead [PR#38409](https://github.com/vllm-project/vllm/pull/38409).
    * Integrated Phase 1 and Phase 2 of CUDA Checkpoint/Restore using the `cuCheckpointProcess` API (driver >= 570), enabling near-zero cold starts for `torch.compile` artifacts [PR#37921](https://github.com/vllm-project/vllm/pull/37921), [PR#37925](https://github.com/vllm-project/vllm/pull/37925).
    * Enhanced `Eagle` speculative decoding by ensuring attention metadata is rebuilt during full CUDA graph execution to improve acceptance rates [PR#38311](https://github.com/vllm-project/vllm/pull/38311).
    * Fixed a critical race condition in the V1 engine where requests aborted during the final execution step were incorrectly reported [PR#38402](https://github.com/vllm-project/vllm/pull/38402).

    * **NVIDIA SM100:** Introduced fused CUDA kernels for DeepSeek MLA decode paths, achieving 2-7x speedups on NVFP4 [PR#38354](https://github.com/vllm-project/vllm/pull/38354) and optimized blockwise FP8 GEMM with `swapAB` support for small-batch efficiency [PR#38325](https://github.com/vllm-project/vllm/pull/38325).
    * **AMD ROCm:** Updated release pipeline to ROCm 7.2.1 and Torch 2.10 [PR#38413](https://github.com/vllm-project/vllm/pull/38413). Added AITER fused kernel support for MLA (RoPE + KV cache fusion) on AMD [PR#38313](https://github.com/vllm-project/vllm/pull/38313).
    * **Intel XPU/CPU:** Enabled per-channel quantization in `compressed-tensors` for XPU [PR#38316](https://github.com/vllm-project/vllm/pull/38316) and updated `ZenCpuPlatform` to correctly handle `supported_dtypes` for AMD Zen CPUs [PR#38236](https://github.com/vllm-project/vllm/pull/38236).

    * Added a Triton-based reference implementation for NVFP4 GEMM using `tl.dot_scaled` to serve as a portable fallback for non-Blackwell hardware [PR#38338](https://github.com/vllm-project/vllm/pull/38338).
    * Resolved precision issues in `DeepGemm` for Qwen3.5 on Blackwell by auto-disabling it to avoid E8M0 scale precision loss across deep layers [PR#38083](https://github.com/vllm-project/vllm/pull/38083).
    * Fused `lora_shrink_expand` Triton kernels to enable Programmatic Dependent Launch (PDL) overlap on SM90+ [PR#38432](https://github.com/vllm-project/vllm/pull/38432).
