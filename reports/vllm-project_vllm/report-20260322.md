# AI Analysis of Pull Requests for vllm-project/vllm during 20260315-20260322

**Key Takeaways:** This week’s development is dominated by a major architectural consolidation of quantization kernels (Marlin/GPTQ/AWQ) and MoE oracles to streamline support for upcoming Blackwell (SM120) and CDNA4 hardware, alongside aggressive stabilization of the V2 Model Runner. Total PRs: 547. Top active areas: (1) MoE and Quantization Refactoring, (2) ROCm/XPU/TPU Hardware Parity, (3) Model Runner V2 & `torch.compile` Optimization, and (4) Responses API & Tool Calling refinements.

1. **Quantization & MoE Refactoring**
    * **Kernel Consolidation:** Major effort to merge redundant quantization paths. `gptq_marlin` is being merged into `gptq.py` ([PR#37770](https://github.com/vllm-project/vllm/pull/37770)), and `awq_marlin` is consolidating legacy AWQ kernels ([PR#37772](https://github.com/vllm-project/vllm/pull/37772)). This removes slow GEMM fallbacks in favor of Marlin kernels for SM75+.
    * **MoE Oracle Pattern:** Standardizing kernel selection via `MoEKernelOracle` base class ([PR#37776](https://github.com/vllm-project/vllm/pull/37776)). Expert kernels (DeepGemm, FlashInfer, Triton) are being migrated to a dedicated `fused_moe/experts/` subdirectory for better modularity ([PR#37761](https://github.com/vllm-project/vllm/pull/37761), [PR#37760](https://github.com/vllm-project/vllm/pull/37760)).
    * **Blackwell (SM120) Support:** Initial routing of SM120 GPUs to CUTLASS MXFP4 MoE backends ([PR#37751](https://github.com/vllm-project/vllm/pull/37751)) and fixes for NVFP4 NaN issues on desktop Blackwell (RTX 5090) by preserving CUDA arch suffixes ([PR#37725](https://github.com/vllm-project/vllm/pull/37725)).
    * **Performance:** Introduced a persistent TopK scheduler for DeepSeek-V3.2 DSA decoding to optimize row-path selection in `CUDAGraph` ([PR#37421](https://github.com/vllm-project/vllm/pull/37421)).

2. **Model Runner V2 & torch.compile**
    * **V2 Speculative Decoding:** Added `CUDAGraph` support for Eagle prefill and drafting phases to reduce CPU dispatch overhead ([PR#37588](https://github.com/vllm-project/vllm/pull/37588)). Draft logits are now explicitly managed within `EagleSpeculator` for graph capture ([PR#37639](https://github.com/vllm-project/vllm/pull/37639)).
    * **Compilation Improvements:** Enabled "Mega AOT Artifacts" for `torch` 2.12+, bundling subgraphs into single artifacts to reduce initialization time ([PR#37198](https://github.com/vllm-project/vllm/pull/37198)).
    * **Heuristic Gating:** Introduced per-matmul heuristic gating for `AsyncTP` to prevent performance regressions at low batch sizes ([PR#37489](https://github.com/vllm-project/vllm/pull/37489)).

3. **Hardware Backends (ROCm, XPU, CPU)**
    * **ROCm (AMD):** Integrated AITER fused `AllReduce` + `RMSNorm` kernels to improve collective communication efficiency ([PR#37646](https://github.com/vllm-project/vllm/pull/37646)). Added support for DeepSeek MLA fused kernels in both prefill and decode paths ([PR#37515](https://github.com/vllm-project/vllm/pull/37515)).
    * **Intel XPU:** Bumped `vllm-xpu-kernels` to v0.1.4 for accuracy fixes ([PR#37641](https://github.com/vllm-project/vllm/pull/37641)) and added support for FP8 `KVCache` ([PR#37731](https://github.com/vllm-project/vllm/pull/37731)).
    * **CPU:** Enabled `tcmalloc` by default in the x86/ARM wheel to optimize memory allocation latency ([PR#37607](https://github.com/vllm-project/vllm/pull/37607)).

4. **Framework Infrastructure & Distributed**
    * **KV Connectors:** New support for 3FS (Alibaba) KVConnector for efficient offloading/sharing ([PR#37636](https://github.com/vllm-project/vllm/pull/37636)). Improved P/D disaggregation for Mamba/Hybrid models by allowing 3 separate RDMA reads for conv states ([PR#37635](https://github.com/vllm-project/vllm/pull/37635)).
    * **Memory Management:** Fixed a critical bug where `KVCache` memory was over-allocated for hybrid Mamba/Attention models (e.g., Qwen3.5) due to improper layer-group accounting ([PR#37124](https://github.com/vllm-project/vllm/pull/37124)).
    * **Speculative Decoding:** Unified the `propose` interface for all drafters (Ngram, Medusa, Eagle) to simplify the `ModelRunner` logic ([PR#37399](https://github.com/vllm-project/vllm/pull/37399)).

5. **Frontend & API (Responses API)**
    * **Reasoning Models:** Added `ToolChoiceRequiredLogitsProcessor` to prevent "thinking" models (R1, QwQ) from skipping tool calls by suppressing EOS tokens during the reasoning phase ([PR#37742](https://github.com/vllm-project/vllm/pull/37742)).
    * **Streaming:** Fixed logic to preserve logprobs for control tokens in tool-calling streams, preventing data loss when `delta_message` is null ([PR#37747](https://github.com/vllm-project/vllm/pull/37747)).
    * **Bugfixes:** Resolved a `previous_response_id` leak where instructions from prior turns were incorrectly carried over ([PR#37727](https://github.com/vllm-project/vllm/pull/37727)).
