# AI Analysis of Pull Requests for pytorch/ao during 20260322-20260329

### Key Takeaways
This week’s activity (63 PRs) is dominated by a major architectural shift toward "v2" quantization via the mass deprecation of legacy layouts, coupled with aggressive performance optimization for MXFP8 training and broad hardware enablement for (1) AMD ROCm (MI300/MI350) and (2) Intel XPU/CPU.

---

### 1. Architectural Cleanup and Deprecation
The framework is undergoing a significant "v1 to v2" transition, moving away from specialized layouts toward a more unified design.
*   **Mass Deprecation:** Multiple PRs removed legacy layouts and code paths, including `PlainLayout` [PR#4151](https://github.com/pytorch/ao/pull/4151), `TensorCoreTiledLayout` [PR#4153](https://github.com/pytorch/ao/pull/4153), `SemiSparseLayout` [PR#4148](https://github.com/pytorch/ao/pull/4148), `BlockSparseLayout` [PR#4143](https://github.com/pytorch/ao/pull/4143), and `QDQLayout` [PR#4146](https://github.com/pytorch/ao/pull/4146).
*   **ABI Stability:** Declared ABI stability as of [PR#4154](https://github.com/pytorch/ao/pull/4154), requiring `torch` 2.11+ for `mxfp8` kernels to utilize stable ABI features.
*   **Version Management:** Version bumped to `0.18.0` [PR#4172](https://github.com/pytorch/ao/pull/4172). Added a flag to suppress version compatibility warnings for python-only users [PR#4165](https://github.com/pytorch/ao/pull/4165).

### 2. High-Performance Training (MXFP8 & MoE)
Heavy focus on Mixture-of-Experts (MoE) performance, specifically targeting DeepSeek-style architectures.
*   **Grouped GEMM:** Introduced tensorwise FP8 grouped GEMM with fused Triton kernels, yielding +18.3% TPS on MI325X for MoE training by eliminating HIP dispatch overhead [PR#4179](https://github.com/pytorch/ao/pull/4179).
*   **CuteDSL Kernels:** Integrated `CuteDSL` for 2D `mxfp8` quantization [PR#4156](https://github.com/pytorch/ao/pull/4156) and registered corresponding sharding rules [PR#4178](https://github.com/pytorch/ao/pull/4178).
*   **Memory Optimization:** Simplified TMA (Tensor Memory Accelerator) synchronization by removing unnecessary memory fences in `mxfp8` kernels [PR#4129](https://github.com/pytorch/ao/pull/4129).

### 3. Hardware Backend Enablement
#### ROCm (AMD)
*   **Comprehensive Enablement:** Enabled FP8 QAT [PR#4132](https://github.com/pytorch/ao/pull/4132), blockwise FP8 inference [PR#4130](https://github.com/pytorch/ao/pull/4130), and low-bit optimizers [PR#4134](https://github.com/pytorch/ao/pull/4134) on MI300/MI350.
*   **Dtype Support:** Added support for AMD-specific `fnuz` FP8 variants in Triton scaling kernels [PR#4135](https://github.com/pytorch/ao/pull/4135) and `BlockwiseQuantLinear` [PR#4136](https://github.com/pytorch/ao/pull/4136).

#### Intel (XPU/CPU)
*   **XPU Support:** Enabled GPTQ [PR#4191](https://github.com/pytorch/ao/pull/4191) and MoE tests [PR#4137](https://github.com/pytorch/ao/pull/4137) for Intel GPUs.
*   **CPU Optimization:** Implemented software prefetching for `scaled_embedding_bag` to hide DRAM latency [PR#4171](https://github.com/pytorch/ao/pull/4171). 
*   **ISA Portability:** Refactored CPU kernels for "build-once, run-everywhere" portability across AVX512, AMX, and AVX10.2 [PR#4159](https://github.com/pytorch/ao/pull/4159).

### 4. Quantization Features & Low-Precision Attention
*   **Fused RoPE/Hadamard:** Added Hadamard support [PR#4194](https://github.com/pytorch/ao/pull/4194) and RoPE fusion detection for "WAN" style models [PR#4173](https://github.com/pytorch/ao/pull/4173) in the low-precision attention API.
*   **Cross Attention:** Added support for different sequence lengths in Q and KV for FP8 attention, achieving 1.5x speedup on Wan2.1-T2V [PR#4142](https://github.com/pytorch/ao/pull/4142).
*   **Granularity:** Expanded `Float8WeightOnlyConfig` to support `PerGroup` granularity [PR#4174](https://github.com/pytorch/ao/pull/4174) and added `aten.embedding` support for `Float8Tensor` [PR#4175](https://github.com/pytorch/ao/pull/4175).
*   **Memory Pinning:** Added support for `MXTensor` and `NVFP4Tensor` pinning to facilitate offloading in `diffusers` [PR#4192](https://github.com/pytorch/ao/pull/4192).

### 5. Developer Experience & Infrastructure
*   **AI Readiness:** Added `CLAUDE.md` [PR#4195](https://github.com/pytorch/ao/pull/4195) and `llms.txt` [PR#4196](https://github.com/pytorch/ao/pull/4196) to improve context for AI coding assistants and LLM crawlers.
*   **CI/Test Improvements:** Standardized blockwise kernel tests with `torch.compile` [PR#4187](https://github.com/pytorch/ao/pull/4187) and consolidated Triton FP8 benchmarks [PR#4166](https://github.com/pytorch/ao/pull/4166).
*   **Bug Fixes:** Resolved a critical tail-handling bug in blockwise FP8 quantization that corrupted scale tensors on ragged shapes [PR#4186](https://github.com/pytorch/ao/pull/4186).
