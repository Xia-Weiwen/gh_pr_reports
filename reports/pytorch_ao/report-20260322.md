# AI Analysis of Pull Requests for pytorch/ao during 20260315-20260322

**Key Takeaways:** This week focuses on an aggressive architectural transition through the total removal of v1 "autoquant" and legacy layouts in favor of v2 `Float8Tensor` and `AffineQuantizedTensor` abstractions, alongside expanded FP8/MXFP8 support for non-CUDA backends across 30 PRs. Top active areas include: (1) Legacy API Deprecation and Refactoring, (2) FP8/MXFP8 training and MoE optimizations, and (3) Cross-hardware enablement for ROCm, XPU, and NPU.

### 1. API Modernization and Deprecations
The framework is undergoing a major cleanup to reduce technical debt by removing legacy v1 quantization paths.
* **Autoquant Removal:** [PR#4122](https://github.com/pytorch/ao/pull/4122), [PR#4121](https://github.com/pytorch/ao/pull/4121), and [PR#4120](https://github.com/pytorch/ao/pull/4120) collectively delete the deprecated `autoquant` v1/v2, `AutoQuantizableLinearWeight`, and associated subgraph utilities.
* **Layout Phase-out:** Legacy `Float8Layout` and `Float8AQTTensorImpl` are removed in [PR#4127](https://github.com/pytorch/ao/pull/4127) and [PR#4123](https://github.com/pytorch/ao/pull/4123), replaced by the unified `Float8Tensor`. [PR#4126](https://github.com/pytorch/ao/pull/4126) deletes `CutlassSemiSparseLayout` in favor of `Sparse2x4CUTLASSFloat8Tensor`.
* **DType Standardization:** [PR#4100](https://github.com/pytorch/ao/pull/4100) deprecates `TorchAODType` (placeholder for sub-8-bit types) as native `torch` now supports `torch.int1` through `torch.int7`.
* **Utility Migration:** `_module_extra_repr` moved to `torchao/quantization/utils.py` to support shared usage between prototype and stable APIs ([PR#4093](https://github.com/pytorch/ao/pull/4093)).

### 2. FP8 and MXFP8 (Microscaling) Training
Significant effort is being directed toward blockwise FP8 and Microscaled formats, particularly for Mixture of Experts (MoE) workloads.
* **Kernel Optimizations:** [PR#4113](https://github.com/pytorch/ao/pull/4113) introduces a fused single-pass Triton kernel for `triton_fp8_per_group_colwise_scales`, reducing HBM traffic from 5 to 3 bytes/element on AMD architectures.
* **Benchmarking:** New kernel-only bandwidth benchmarking scripts for blockwise FP8 quantization were added to track effective IO bandwidth against device peaks ([PR#4128](https://github.com/pytorch/ao/pull/4128), [PR#4112](https://github.com/pytorch/ao/pull/4112)).
* **Precision and Permutation:** [PR#4117](https://github.com/pytorch/ao/pull/4117) fixes `exp2f_rcp` handling for unbiased exponents of 127 in `mxfp8`. [PR#4102](https://github.com/pytorch/ao/pull/4102) adds permute support for alignment=0 to accommodate Expert Parallel (EP) token grouping in MoE.
* **New Kernels:** A `CuTeDSL` kernel for 3D tensor quantization to `MXFP8` has been introduced ([PR#4089](https://github.com/pytorch/ao/pull/4089)).

### 3. Multi-Backend & Hardware Enablement
The repository is actively expanding support for non-NVIDIA hardware.
* **ROCm (AMD):** 
    * Enabled Float8 dynamic activation quantization on Navi4 (gfx1200/1201) hardware ([PR#4108](https://github.com/pytorch/ao/pull/4108)).
    * Enabled `MXFP8` MoE training kernels and grouped GEMM tests for MI300X ([PR#4110](https://github.com/pytorch/ao/pull/4110)).
    * Enabled Int4 weight-only quantization (`TILE_PACKED_TO_4D`) on ROCm ([PR#4092](https://github.com/pytorch/ao/pull/4092)).
* **XPU (Intel):** Added support for blockwise FP8 in `inference.py` ([PR#4096](https://github.com/pytorch/ao/pull/4096)).
* **X86 (CPU):** Optimized `intmm` to use `u8s8` matmuls when only `avx512-vnni` is available ([PR#4103](https://github.com/pytorch/ao/pull/4103)).
* **NPU:** Initial Work-in-Progress (WIP) support for FP8 and Int4 formats ([PR#4124](https://github.com/pytorch/ao/pull/4124), [PR#4087](https://github.com/pytorch/ao/pull/4087)).

### 4. Bug Fixes and Performance Refinements
* **SAM2 Optimization:** Replaced custom complex-number RoPE with `F.apply_rotary_emb` to eliminate `view_as_complex` overhead and improve `torch.compile` fusion ([PR#4118](https://github.com/pytorch/ao/pull/4118)).
* **GEMM Dispatching:** Fixed a false positive in `_is_128_128_scaled` where PerTensor scaling on 128x128 weights incorrectly routed to blockwise kernels ([PR#4091](https://github.com/pytorch/ao/pull/4091)).
* **Precision Validation:** Fixed operand precision compatibility checks for FP8 to correctly compare `cc2` compute capabilities ([PR#4115](https://github.com/pytorch/ao/pull/4115)).
* **Inference Mode:** Fixed a dispatcher failure for `LinearActivationQuantizedTensor` when executing `aten._has_compatible_shallow_copy_type` in inference mode ([PR#4098](https://github.com/pytorch/ao/pull/4098)).
* **CI Maintenance:** Skipped failing `DTensor` tests caused by upstream PyTorch changes ([PR#4119](https://github.com/pytorch/ao/pull/4119)) and fixed `hipSPARSELt` guards for environments without AMD sparse library support ([PR#4125](https://github.com/pytorch/ao/pull/4125)).
